# DeepSeek＋本地文字知识库试用版

此版本保留现有 Coze 聊天链路作为回退。独立的 `/agent-studio` 页面统一管理智能体、DeepSeek/Coze API 密钥、聊天服务切换、各智能体独立的提示词与思考程度，以及文字知识库。默认仍选 Coze；数据库迁移新增知识库表、产品检索索引、产品资料字段和智能体指令字段，不删除旧数据。当前是本地试用代码，线上环境是否已部署需另行核对。

## 试用步骤

1. 部署后打开 `/agent-studio` 的「API 设置」，填写 DeepSeek API Key。也可以在部署环境设置 `DEEPSEEK_API_KEY`；后台保存的密钥优先。可通过 `DEEPSEEK_MODEL` 指定模型，默认 `deepseek-flash`。
2. 打开 `/agent-studio`，选择子智能体进入其独立提示词页面（如 `/agent-studio/agents/aura`），把 Coze 中的角色设定复制到对应提示词。原「快捷消息」只是前台点击后发送的文字，不是系统指令。
3. 在 `/agent-studio` 的「文字知识库」新增、编辑、搜索或删除资料，也可粘贴资料，或上传 UTF-8 TXT/MD、Word DOCX，选择可检索它的智能体。即使服务器在线上，也只需从自己电脑的浏览器打开线上 `/agent-studio` 并选择本地文件：浏览器把文件发给服务器，服务器提取文字后写入 `DATABASE_DIR/ai_customer_service.db`，不保留原文件。单份正文最多 20 万字；TXT/MD 最多 600 KB，DOCX 最多 5 MB。Word 的正文段落和表格会提取为文字；图片中的文字不会识别。旧版 `.doc` 请先另存为 `.docx`。
4. 在每个子智能体的独立页面选择思考程度：关闭、低、高、最高。各智能体互不影响；关闭默认更快，更高档位可能增加等待时间和模型用量。思考内容不展示、不保存。升级时旧全局档位会复制给现有智能体一次。
5. 将聊天服务切到「DeepSeek＋本地知识库」并保存。先用已知产品问题、使用问题、资料中明确的安全问答和无资料问题试用四个入口。异常时在同一设置处切回 Coze。

## 产品理解与扩展检索

后台「产品管理」现在可以填写主要成分与含量、适用场景与依据、注意事项。已有产品的名称、简介、亮点和详情会在升级时自动建立检索索引；以后新增、修改、删除产品时索引同步更新，无需重复上传到文字知识库。详情中的 HTML 标签和图片地址不会进入检索文本。成分和适用场景仍需人工核实，系统不会从图片自动识别标签。

DeepSeek 回答前先检索用户当前提问。若首次结果已有产品或资料覆盖问题所需信息，直接生成回答，不调用检索词规划模型；完全没有命中资料的普通常识问题也直接回答。宽泛营养需求、指代前文、明显在问产品或营养补充、产品推荐缺少候选，以及已有资料但使用/成分/功效或安全信息缺失时，才结合最近对话、首次检索结果和最多 40 个产品的简要目录生成最多两个补充检索词，重新检索原始资料。当前“是否足够”由轻量关键词规则近似判断，并非模型逐条审查证据。扩展词只用于找资料，不直接作为回答依据。每轮最多提供 4 个产品和 4 个文字资料片段给最终回答；规划调用失败时退回首次检索结果。触发扩展时会多一次 DeepSeek 请求，可能增加等待时间和 API 用量。

例如只有“A 产品含蛋白质”的资料，而用户说“缺营养可以吃点啥”，扩展检索可以找到 A 产品，但回答应先确认具体营养目标，或以“如果是蛋白质摄入不足”为条件介绍 A 的资料依据，不能直接断定用户缺蛋白质。可用“蛋白质吃得少怎么办”“缺营养可以吃点啥”“刚才那个产品有什么注意事项”等问题验收。宽泛需求、资料不完整或特殊人群问题仍可能需要人工确认。

### 没有命中资料时怎么回答

DeepSeek 链路会先回答能用通用知识回答的部分，给出可执行的建议；宽泛问题可在回答后再问一个关键澄清问题，不应只说“请补充问题”。没有可核实的产品资料时，不编造某款产品的成分、功效或适用性，也不借通用成分知识推断具体产品一定有效。日常回答聚焦用户所问，不主动延伸到产品争议或负面话题，也无需刻意夸赞；若用户直接询问过敏、禁忌、特殊人群、质量或其他安全问题，须如实说明资料中的限制，无法核实时明确说无法确认。

这项回答规则只作用于切换后的 DeepSeek 聊天链路。仍使用 Coze 时，回答策略由原 Coze 智能体决定。实际自然语言回答仍需用真实 DeepSeek Key 验收。

本版用 SQLite FTS5 trigram 做中文文字检索，不需要 embedding API 或独立向量数据库。检索到的片段只供当前智能体使用；回答引用的资料 ID 仅记在服务端日志。人工转接、前台聊天接口、排队和历史记录沿用现有实现。案例网页 AI 识别等其他旧 Coze 功能暂未迁移，不能在 Coze 停服前直接删除旧密钥。

## 本地验证与接口

在项目根目录安装 `requirements.txt`，设置长度至少 32 位的 `SECRET_KEY`，将 `DATABASE_DIR`、`UPLOAD_DIR` 指向测试目录，再启动 Flask。首页为 `http://127.0.0.1:5001/`，后台为 `http://127.0.0.1:5001/admin`。建议先备份已有 SQLite 数据库或使用独立测试库；本地和线上数据库不会自动同步。Python 代码变化后重启服务，前端变化后刷新页面。管理员创建方式见根目录 `HANDOFF.md`。

聊天接口仍为 `POST /api/chat/send`（同步）和 `POST /api/chat/stream`（SSE 流式），排队请求也复用同一服务切换；知识库管理接口为 `GET/POST /api/admin/knowledge`、`GET/PUT/DELETE /api/admin/knowledge/<id>`，需要管理员身份；列表接口可用 `q` 和 `agent_id` 筛选。前台提问的回答链路是：读取最近已完成对话 → 首次检索 → 按需扩展检索 → 结合原始资料生成回答 → 保存聊天记录。默认最多带入 6 轮历史，每条最多 2000 字符，可由 `CHAT_CONTEXT_ROUNDS`、`CHAT_CONTEXT_MESSAGE_MAX_CHARS` 调整。

建议分别用“某产品含什么成分”（应跳过扩展）、“缺营养可以吃点啥”（应条件推荐或追问）、“这个呢”（检验前文指代）、“该产品孕妇能吃吗”（检验安全资料缺口）验收。未配置真实 DeepSeek Key 时，只能验证页面、上传、索引和本地分支逻辑，不能据此断言最终回答质量。

上线前备份生产 SQLite 数据库，并确保 `DATABASE_DIR` 位于持久化磁盘；文字知识库和产品索引都存于其中。切换由数据库设置控制，所有用户会同时使用选中的聊天服务；试用宜先在测试环境进行。实际回答质量和超时情况需用真实资料与 DeepSeek Key 验收。
