# 营养师工作台：咨询留档、导出与历史回复规划

## 1. 目标与边界

营养师工作台在不干扰当前排队、接入和回复流程的前提下，补齐三个能力：

1. 已结束咨询可检索、查看并长期留档。
2. 营养师能查看同一用户过往的提问和真人回复，避免重复询问。
3. 支持导出单次、批量或筛选结果，便于复盘和运营分析。

现有 `handoff_sessions`、`handoff_messages` 和转接时保存的 AI 上下文已经具备 V1 留档基础。第一期直接把 `closed` 会话视为已归档，不复制消息、不改变当前状态机，也不影响前台恢复 AI。

“归档”和“删除”必须分开：归档仅代表退出当前工作队列，原始记录仍保留；后续如需删除，应设计独立权限和二次确认。

## 2. 页面规划

### 2.1 左侧会话区

在“咨询会话”下增加两个页签：

- **进行中**：保留当前“分配给我 / 等待队列”。
- **咨询档案**：展示已结束会话，默认按结束时间倒序。

档案列表提供以下筛选：

- 日期范围
- 用户姓名或团队
- 问题/回复关键词
- 接待营养师
- 服务方式：在线咨询、留言

列表每项展示：用户、最后一个有效问题、最后一条营养师回复、接待人、结束时间。采用服务端分页，每页默认 20 条。

### 2.2 中间详情区

打开档案后进入只读模式，按时间顺序显示：

- 转人工前的 AI 问答上下文
- 用户发送给真人的消息
- 营养师回复
- 接入、转留言、结束等关键时间点

顶部显示“导出本次咨询”和“复制回复”操作。历史档案不能重新接入或发送消息，防止误把新回复写入已关闭会话。

### 2.3 右侧资料区

右侧调整为两个页签：

- **用户资料**：姓名、团队、当前状态。
- **历史咨询**：按时间倒序显示同一 `user_id` 的历史会话，展示最近问题、营养师回复摘要和结束时间；点击后在中间区域只读查看。

当前会话和历史会话应有明显标识。从历史详情返回后，恢复此前正在处理的会话，避免营养师丢失工作现场。

### 2.4 导出入口

提供三级入口：

- 详情页导出单次咨询。
- 档案列表多选后批量导出。
- 按当前筛选条件导出结果。

V1 采用带 UTF-8 BOM 的 CSV，确保 Excel 直接打开中文不乱码。批量导出设最大 5,000 条；超过上限时要求缩小筛选范围。后续如确有排版需求，再增加 PDF，不在第一期同时实现。

## 3. 接口设计

所有接口放在 `/api/admin/handoff` 下并继续使用 `admin_required`。

### 3.1 档案列表

`GET /api/admin/handoff/archive`

查询参数：

- `page`、`limit`
- `from`、`to`
- `keyword`
- `team`
- `agent_id`
- `service_mode=live|message`

返回分页信息以及列表摘要，不返回完整消息，避免轮询和列表加载过重。

### 3.2 档案详情

`GET /api/admin/handoff/archive/<session_id>`

返回会话基础信息、AI 上下文、真人消息、关键时间点。仅允许读取已结束会话。

### 3.3 用户历史咨询

`GET /api/admin/handoff/users/<user_id>/history?page=1&limit=20`

默认只返回已结束记录；必要时用 `exclude_session_id` 排除当前会话。用户关联必须使用稳定的 `user_id`，不能仅按姓名匹配。

### 3.4 导出

`POST /api/admin/handoff/export`

请求体二选一：

- `{ "session_ids": ["..."] }`
- `{ "filters": { ...与档案列表相同的筛选条件... } }`

响应为 CSV 下载流。导出字段建议包含：

- 会话编号、用户、团队、接待营养师
- 服务方式、结束原因
- 创建、分配、接入、结束时间
- 等待时长、处理时长
- 首个问题、最后问题
- 全部用户问题、全部营养师回复

导出文件不包含转人工前的 AI 对话；AI 上下文仅在客服台内用于接待参考，避免导出内容冗余。

## 4. 数据与安全

### 4.1 V1 数据策略

- 直接查询现有已关闭会话与消息，不新增归档副本。
- 保留 `query_type` 后台字段以兼容历史数据，但不再在客服台展示或作为卡片兜底文案。
- 统一由数据库查询排序、筛选和分页，前端不一次性加载全部档案。
- 时间接口统一输出 UTC/ISO 8601，前端按本地时区显示。

### 4.2 权限建议

当前系统只有管理员权限时，V1 可先沿用 `admin_required`。如果后续区分营养师和主管：

- 营养师默认只能查看、导出自己接待的记录。
- 主管可查看和导出全部记录。
- 当前进行中且属于其他营养师的会话，不应通过历史接口绕过归属校验。

### 4.3 导出安全

- 对以 `=`, `+`, `-`, `@` 开头的 CSV 单元格加前导单引号，避免表格公式注入。
- 不导出 JWT、API Key、Bot ID 等系统配置。
- 批量导出可按权限脱敏用户信息。
- 通过 `handoff_export_logs` 记录导出审计：操作人、时间、筛选条件或会话编号、导出条数。

### 4.4 可选的增强字段

当出现人工整理需求后，再通过 migration 增加独立的 `handoff_archive_meta`，保存：

- `session_id`
- `archive_note`
- `tags_json`
- `follow_up_status`
- `follow_up_at`
- `updated_by`、`updated_at`

不建议直接修改原始消息；备注、标签和原始记录分开保存，便于审计。

## 5. 分期实施

### 第一期：可查可看

- 咨询档案页签、筛选、分页
- 档案只读详情
- 同一用户历史咨询
- 当前会话与历史查看的无损切换

### 第二期：可导出可审计（已完成）

- 单次、多选、按筛选条件导出 CSV
- 行数上限、公式注入防护、权限检查
- 导出审计日志

### 第三期：可运营

- 档案备注、标签、待跟进状态
- 主管权限和团队维度统计
- 高频问题、平均等待与处理时长报表

## 6. 验收清单

- 会话关闭后立即出现在档案列表，不再占用当前接待数。
- 姓名、团队、关键词、日期、营养师和服务方式筛选结果正确。
- 当前咨询中可以查看同一用户的历史回复，返回后输入内容和会话选中状态不丢失。
- 历史档案只读，不能误发送消息或重新接入。
- 在线咨询与留言模式的消息都能完整留档。
- 单次、多选和筛选导出的内容、顺序与页面一致，中文可由 Excel 正常打开。
- CSV 公式字符受到防护，越权读取和越权导出被拒绝。
- 5,000 条上限、空结果、跨时区边界和已删除用户等异常场景有明确反馈。
- 档案查询和导出不会影响当前队列轮询、接入、回复及前台恢复 AI。

## 7. 推荐开发顺序

优先完成“档案列表 → 档案详情 → 用户历史”，让营养师先具备查阅能力；随后实现 CSV 导出及审计；最后再根据真实使用反馈增加备注、标签和跟进任务。这样无需先扩展数据库，就能以最低风险交付第一版。
